## 3. Сбор требований к системе

На основе анализа предметной области были сформированы требования к информационной системе «Электронная карта пациента».

---

### 📋 Функциональные требования

| ID | Требование | Описание |
|----|------------|----------|
| **FR-01** | Регистрация пациентов | Система обеспечивает регистрацию новых пациентов с внесением всех необходимых персональных данных (ФИО, дата рождения, пол, телефон, адрес, полис, СНИЛС) |
| **FR-02** | Хранение электронных карт | Система должна хранить электронные карты пациентов в структурированном виде с возможностью долгосрочного хранения и архивирования |
| **FR-03** | Поиск пациентов | Система обеспечивает поиск пациентов по различным критериям (ФИО, номер полиса, СНИЛС, дата рождения) |
| **FR-04** | Запись на приём | Система предоставляет возможность записи пациента к врачу с выбором даты, времени и цели визита |
| **FR-05** | Управление расписанием | Система содержит и поддерживает актуальное расписание работы врачей с учётом занятости |
| **FR-06** | Ведение медицинских записей | Система обеспечивает внесение диагнозов, назначений и рекомендаций в электронную карту пациента |
| **FR-07** | Просмотр и редактирование | Система обеспечивает просмотр и редактирование медицинских записей с сохранением истории изменений |
| **FR-08** | Формирование выписки | Система должна формировать выписной эпикриз на основе внесённых данных о лечении |
| **FR-09** | Оформление больничного листа | Система обеспечивает оформление листка нетрудоспособности с присвоением уникального номера |
| **FR-10** | Формирование отчётности | Система обеспечивает генерацию внутренних и внешних отчётов (загрузка врачей, статистика обращений) |
| **FR-11** | История обращений | Система обеспечивает сохранение полной истории взаимодействий пациента с медицинской организацией |

---

### ⚙️ Нефункциональные требования

| ID | Требование | Описание |
|----|------------|----------|
| **NFR-01** | Удобство интерфейса | Интерфейс системы должен быть понятным и удобным для всех категорий пользователей (врачи, регистраторы, администраторы) |
| **NFR-02** | Надёжность хранения | Система обеспечивает надёжное хранение данных с регулярным резервным копированием (ежедневно) |
| **NFR-03** | Производительность | Время выполнения основных операций (поиск пациента, открытие карты, сохранение записи) должно составлять не более 2-3 секунд |
| **NFR-04** | Безопасность доступа | Система обеспечивает разграничение прав доступа в зависимости от роли пользователя; хранение паролей в хэшированном виде |
| **NFR-05** | Расширяемость | Архитектура системы должна обеспечивать возможность добавления новых модулей без существенной переработки существующих |
| **NFR-06** | Достоверность данных | Система обеспечивает достоверность данных (валидация ввода, защита от несанкционированного изменения, логирование действий) |
| **NFR-07** | Сопровождаемость | Система должна быть удобной для сопровождения и тестирования (модульная структура, логирование, документация) |
| **NFR-08** | Доступность | Система должна быть доступна 99.5% времени (простои не более 3.5 часов в месяц) |

---

### 👥 Роли пользователей

| Роль | Обязанности |
|------|-------------|
| **Администратор** | Управление пользователями, настройка прав доступа, администрирование базы данных, резервное копирование, мониторинг работы системы, управление справочниками |
| **Регистратор** | Регистрация новых пациентов, создание электронных карт, запись пациентов на приём, просмотр расписания, выдача направлений |
| **Врач** | Просмотр электронных карт пациентов, внесение диагнозов и назначений, формирование выписок, оформление больничных листов, анализ истории обращений |

### 📌 Заключение

Собранные функциональные и нефункциональные требования охватывают все ключевые процессы медицинской организации:

- **11 функциональных требований** — от регистрации пациентов до формирования отчётности
- **8 нефункциональных требований** — от удобства интерфейса до доступности системы
- **3 роли пользователей** — с чётким разграничением обязанностей

Данные требования являются основой для разработки технического задания и последующей реализации информационной системы «Электронная карта пациента».
