## 3. Сбор требований к системе

На основе анализа предметной области были сформированы требования к системе управления медицинской лабораторией.

---

### 📋 Функциональные требования

| ID | Требование | Описание |
|----|------------|----------|
| **FR-01** | Регистрация пациентов | Система обеспечивает регистрацию пациентов с внесением всех необходимых персональных данных |
| **FR-02** | Хранение данных пациентов | Система должна хранить данные о пациентах в структурированном виде с возможностью долгосрочного архивирования |
| **FR-03** | Поиск пациентов | Система обеспечивает поиск пациентов по различным критериям (ФИО, номер карты, дата рождения) |
| **FR-04** | Назначение анализов | Система предоставляет возможность назначать один или несколько анализов в рамках одного заказа |
| **FR-05** | Справочник анализов | Система содержит и поддерживает актуальный справочник анализов с референсными значениями |
| **FR-06** | Ввод результатов | Система обеспечивает внесение результатов исследований (как вручную, так и автоматически) |
| **FR-07** | Просмотр и редактирование | Система обеспечивает просмотр и редактирование результатов исследований с сохранением истории изменений |
| **FR-08** | Формирование протоколов | Система должна формировать протоколы исследований на основе внесённых данных |
| **FR-09** | Выдача бланков | Система обеспечивает предоставление готовых бланков и протоколов (печать, электронная отправка) |
| **FR-10** | История анализов | Система обеспечивает сохранение истории анализов пациента для отслеживания динамики |

---

### ⚙️ Нефункциональные требования

| ID | Требование | Описание |
|----|------------|----------|
| **NFR-01** | Удобство интерфейса | Интерфейс системы должен быть понятным и удобным для всех категорий пользователей |
| **NFR-02** | Надёжность хранения | Система обеспечивает надёжное хранение данных с регулярным резервным копированием |
| **NFR-03** | Производительность | Время выполнения основных операций (поиск, открытие заказа, сохранение) должно составлять не более 2-3 секунд |
| **NFR-04** | Безопасность доступа | Система обеспечивает разграничение прав доступа в зависимости от роли пользователя |
| **NFR-05** | Расширяемость | Архитектура системы должна обеспечивать возможность расширения функционала без существенной переработки существующих модулей |
| **NFR-06** | Достоверность данных | Система обеспечивает достоверность данных (валидация ввода, защита от несанкционированного изменения) |
| **NFR-07** | Сопровождаемость | Система должна быть удобной для сопровождения и тестирования (модульная структура, логирование, документация) |

---

### 👥 Роли пользователей

| Роль | Обязанности |
|------|-------------|
| **Администратор** | Управление пользователями, настройка прав доступа, администрирование базы данных, резервное копирование, мониторинг работы системы |
| **Регистратор** | Регистрация пациентов, создание заказов на анализы, печать штрих-кодов и направлений, выдача готовых результатов |
| **Лаборант** | Приём и маркировка биоматериала, внесение результатов исследований, контроль качества, формирование протоколов |
| **Врач / Оператор** | Просмотр протоколов исследований, анализ результатов, получение уведомлений о критических показателях, формирование заключений |

### 📌 Заключение

Собранные функциональные и нефункциональные требования охватывают все ключевые процессы медицинской лаборатории:

- **10 функциональных требований** — от регистрации пациентов до формирования истории анализов
- **7 нефункциональных требований** — от удобства интерфейса до сопровождаемости системы
- **4 роли пользователей** — с чётким разграничением обязанностей

Данные требования являются основой для разработки технического задания и последующей реализации системы.
