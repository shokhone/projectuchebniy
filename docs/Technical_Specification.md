# Технические характеристики

## 1. Назначение системы

Информационная система «Электронная карта пациента» предназначена для автоматизации процессов медицинской организации, включая:

- ведение электронных карт пациентов;
- запись на приём к врачам;
- оформление выписок и больничных листов;
- формирование отчётности.

---

## 2. Функциональные требования

### 2.1. Модуль ввода карточки пациента
- Регистрация нового пациента с заполнением полей: ФИО, дата рождения, пол, адрес, контактный телефон, номер полиса (ОМС/ДМС).
- Проверка уникальности пациента по номеру полиса и СНИЛС.
- Автоматическое создание электронной карты с присвоением уникального идентификатора.

### 2.2. Модуль записи на приём
- Просмотр расписания работы врачей.
- Выбор врача по специальности.
- Выбор доступной даты и времени.
- Фиксация записи с указанием цели визита.
- Отмена и перенос записи.
- Автоматическая проверка на пересечение записей (один пациент не может быть записан к двум врачам в одно время).

### 2.3. Модуль выписки
- Формирование выписного эпикриза по итогам лечения.
- Указание диагноза (основного и сопутствующих) по классификатору МКБ-10/МКБ-11.
- Сохранение назначений и рекомендаций.
- Закрытие случая лечения с фиксацией даты выписки.

### 2.4. Модуль больничного листа
- Оформление листка нетрудоспособности.
- Указание периода нетрудоспособности (с ... по ...).
- Формирование номера больничного по установленному формату.
- Печать бланка больничного листа.

### 2.5. Модуль отчётности
- Формирование отчёта по загрузке врачей (количество приёмов за период).
- Формирование отчёта по структуре обращений (по специальностям, диагнозам).
- Экспорт отчётов в форматы: PDF, Excel (XLSX), CSV.

## 3. Нефункциональные требования

| Требование | Значение |
| :--- | :--- |
| **Производительность** | Время отклика системы — не более 2 секунд при одновременной работе до 50 пользователей |
| **Доступность** | 99.5% (простои не более 3.5 часов в месяц) |
| **Безопасность** | Ролевая модель доступа (администратор, врач, регистратор); хранение паролей в хэшированном виде (password_hash); HTTPS для веб-версии; защита от SQL-инъекций (PDO/prepared statements) |
| **Надёжность** | Автоматическое резервное копирование базы данных ежедневно |
| **Масштабируемость** | Возможность добавления новых модулей без изменения существующих |
| **Удобство использования** | Интуитивно понятный интерфейс, минимум действий для основных операций |

## 4. Архитектура системы

### 4.1. Общая архитектура
Клиент (Веб-браузер)
↓
Frontend (HTML/CSS/JS)
↓
Backend (PHP 8+)
↓
База данных (MySQL/PostgreSQL)

### 4.2. Модульная структура

| Модуль | Описание |
| :--- | :--- |
| **Модуль аутентификации** | Вход в систему, управление сессиями, ролевой доступ |
| **Модуль пациента** | Управление карточками пациентов, поиск, фильтрация |
| **Модуль расписания** | Управление расписанием врачей, запись на приём |
| **Модуль медицинских записей** | Ведение анамнеза, диагнозов, назначений |
| **Модуль документооборота** | Формирование выписок, больничных листов |
| **Модуль отчётности** | Генерация и экспорт отчётов |
